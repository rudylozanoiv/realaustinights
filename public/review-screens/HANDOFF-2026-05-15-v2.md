## 2. Modal-open bug — diagnosis and current hypothesis

**Reproduction (Playwright @ 1440×900, dev server http://127.0.0.1:3001):**
1. Load `/`
2. Click header **Sign Up** OR scroll to `#membership` and click **Join Membership**
3. URL hash becomes `#signup`
4. **No modal renders.** `welcome_text_visible: false`, `document.querySelectorAll('.fixed.inset-0.z-50').length === 0`, `document.querySelector('form') === null`.
5. Setting hash directly via `window.location.hash = '#signup'` after page load **also fails** to open the modal.
6. Direct load with `http://127.0.0.1:3001/#signup` **also fails**.

**No JS console errors.** Only HMR WebSocket handshake failures (unrelated dev-tooling noise — but see §3).

**Wiring (verified by re-reading the code):**
- `app/page.tsx`: maintains `showSignup` state. Inline `onSignUpClick={() => { setShowSignup(true); window.location.hash = 'signup'; }}` passed to `HomepageShell`.
- `HomepageShell` → `LockedHeader` and `FooterRoutingSection` receive `onSignUpClick`.
- `SignupModal` is always mounted; `open={showSignup}`; returns `null` if `!open`.
- `useEffect` on mount: registers a `hashchange` listener that calls `setShowSignup(window.location.hash === '#signup')` and also fires once synchronously.

**Logically** the chain should work for all three trigger paths. The empirical failure suggests either (a) stale served bundle (see §3), or (b) a hydration / React-state ordering bug that the source-level read didn't surface.

**Mitigations applied (this session) make the wiring more robust regardless of root cause:**
- Anchors → buttons eliminates the default anchor navigation racing with the click handler.
- The click handler still sets state AND hash — the hashchange listener remains a backup path.

**Next agent should:** restart `npm run dev` (cleanly kill PID 21374, re-run), then re-run `node .artifacts/rescue-screens/check-join-membership.mjs`. If the test still fails post-restart, the bug is genuine state-management, not stale-bundle, and root cause needs to be found in `app/page.tsx` or `signup-modal.tsx`.

## 4. Earlier morning session — profile-row blocker resolution (canonical record)

This is condensed; the full play-by-play lives in `2026-05-15-openclaw-realaustinights-handoff.md`.

**Schema reality (was misdiagnosed before today):**
- `public.users` is a **founding-member tracker**: `id bigint NOT NULL` (no default), `email text NOT NULL`, `is_founding_member boolean NOT NULL`, `founding_member_number integer`. Email is the natural key via `lower(trim(email))` unique index. CANNOT be FK-linked to `auth.users.id` because of type mismatch.
- `public.profiles` is the **auth-linked profile table** — created today via Supabase Dashboard SQL Editor.

**SQL applied (NOT in repo — lives only in Supabase):**
```sql
create table public.profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  email text,
  instagram_handle text,
  x_handle text,
  phone text,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);
alter table public.profiles enable row level security;

create or replace function public.handle_new_user()
returns trigger language plpgsql security definer
set search_path = public as $$
begin
  insert into public.profiles (id, email, instagram_handle)
  values (new.id, new.email, nullif(new.raw_user_meta_data->>'instagram', ''))
  on conflict (id) do nothing;
  return new;
end; $$;

create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.handle_new_user();
```

**Verifications (already passed today):**
- `profiles_table_exists, profiles_column_count, rls_enabled_count = true, 7, 1`
- `handle_new_user_function_count, on_auth_user_created_trigger_count = 1, 1`
- `auth_users_count, profiles_count, matched_rows_count = 3, 3, 3` (backfill confirmed)
- Synthetic admin-created user → trigger fires → row appears in `public.profiles`

**Still pending on the Supabase side:**
- RLS **policies** on `public.profiles` (RLS is enabled but no policies → app reads will be blocked once the app actually queries). Recommend authenticated `SELECT`/`UPDATE` where `id = auth.uid()`.
- Founding-member promotion remains a manual operation against `public.users` keyed on `lower(trim(email))`.
